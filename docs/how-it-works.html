Tool routing before the expensive prompt.

Hermes Tool Router narrows the tool schema before Hermes assembles the final model request. Obvious turns stay local with deterministic rules; ambiguous turns can use a tiny classifier model; unsafe or uncertain cases fall open to the full toolset.

Pre-turn hook Fail-open Small router model request_toolset recovery

Routing flow

1 User turn arrives The plugin receives the latest user message through pre_turn_context_build, before the prompt and tool schemas are assembled.
→
2 Classify required toolsets Deterministic rules try obvious intents first. If they cannot classify the turn, a small router model can return JSON like {"toolsets":["file"]}.
→
3 Send a smaller tool surface Hermes receives only the predicted tools plus any configured floor toolsets and the recovery tool.

Fast local path

For clear requests like “read this file” or “search the web,” deterministic rules route immediately. No prompt text leaves the machine.

  • No router API call
  • Lowest latency
  • Covers obvious intent patterns

Small-model path

For ambiguous turns, the plugin sends a short classifier prompt to a small OpenAI-compatible model. If it times out, errors, or lacks credentials, Hermes keeps the full toolset.

  • Uses up to first 1,500 message characters
  • Requires JSON-following router model
  • Fails open to avoid dropped capabilities
